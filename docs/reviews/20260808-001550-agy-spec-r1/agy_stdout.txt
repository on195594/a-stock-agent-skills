## 5. 安全边界评估 (Safety Boundary Assessment)

### 5.1 SQLite Backup API 与 WAL Checkpoint 澄清（特别复核）
- **先前 AGY 说法纠正**：此前 AGY 关于“SQLite Backup API 必须先执行 TRUNCATE checkpoint”的说法在技术上是**不准确**的。
- **技术事实**：SQLite 的 Online Backup API (`sqlite3_backup_init` / `step` / `finish`，即 Python 的 `sqlite3.Connection.backup`) 会自动读取主 `.db` 文件及活跃的 `-wal` 日志文件，生成一份事务一致的完整数据库镜像。在 Backup 过程中，无需提前进行 `TRUNCATE` checkpoint。
- **Spec Section 10.2 判定**：Spec Section 10.2 明确指出：“WAL checkpoint 可以在无活跃 writer 且锁可控时作为维护步骤，但不是替代 Backup API 的充分条件。”**Spec 本文的这一表述是完全正确且严谨的**，无需按先前错误说法修改。

### 5.2 Cron、Telegram 与并发 Safe Boundary
- Spec 规定所有 Shadow/Fixture 测试必须使用临时 XDG 状态目录（`A_STOCK_STATE_DIR`），禁止复用生产 `cache.db`。
- 外部通知 (E1 - Telegram) 在测试和 shadow 模式下默认强制关闭，且不可注入生产 Token，具备良好的 fail-closed 特性。
- 生产切换 (M7) 显式要求独立的人工批准门禁，符合安全风险隔离原则。
