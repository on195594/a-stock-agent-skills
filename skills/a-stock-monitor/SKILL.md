# A股持仓监控

## 写入安全边界

持仓、交易账本、预警、L3 和 Tier 写入属于 W1：用户确认具体动作后，才可在子命令前追加全局 `--confirm-write`。缺少该参数时 CLI 返回 3 且不改变数据库。行情或状态无法验证时必须 fail-closed，不得把推测当作触发事实。

> 本 skill 专用于**已持仓**股票的监控和卖出决策。初次分析和买入判断请使用 `/a-stock-research`。
> 明确声明“不做交易判断”的公开数据子任务（仅报价、指数、行业对照或宏观证据）不得加载本 skill；由持有账户、本地 alerts/L3 与最终操作判断的父级加载并执行 C01—C10。
> 版本变更历史（案例来源、审查过程、修复细节）见 `CHANGELOG.md`，正文只保留可执行规则本身。

## 单股泛化请求的快速交付合同

用户只说“研究一下/看看这只股票”且账本确认已持仓时，执行单股持仓复核并默认输出精简结论；C01—C10仍须全部完成，精简只压缩展示和低价值检索，不得省略风险门禁。用户明确要求详细审计，或出现重大公告、异常波动、L3/止损/治理条件接近触发、关键来源冲突时，再展开完整证据报告。

来源顺序固定为：交易所/监管正式披露 → 公司正式报告与投资者关系材料 → 结构化数据提供者 → 聚合检索补缺。官方入口可用时不得为同一公告重复搜索；聚合检索最多一个批次，首批结果系统性无关时立即停用该来源。正式报告提取最多使用两种方法：结构化文档提取一次，失败后浏览器原生下载并本地提取一次；两者均失败时报告缺口并按既有 fail-closed 规则处理，不继续堆叠同类回退。

行情、估值和技术数据优先复用 `a-stock-fetch` 及其已安装 runtime provider；runtime 已取得数据时不得先探测临时第三方库。报告正文只对明确的单个文件执行一次有界提取，限制输入大小和每类命中上下文，不扫描整个临时目录。monitor 路径不得创建首次研究评分任务；`a-stock-qa` 的 monitor rubric 尚未实现，monitor 任务不得加载或调用该 Skill，合规项直接标记 `SKIP`。

紧凑命令若因安装态 runtime 尚未升级而返回 `unrecognized arguments`，本轮只降级到原有 `holdings` / `alerts` / `l3-list` 文本视图并标注 runtime 缺口；不得为一次监控自行安装或切换生产 runtime。

## 任务级执行闭环

本 Skill 是持仓操作判断的 Primary Skill。开始调用领域工具前，用当前会话的 `todo` 建立 C01—C10 临时检查项；Supporting Skills 只提供证据，不接管完成判定。尚未判断适用性时保持 `pending`，取得框架和任务范围后再关闭不适用项。

`todo` 只使用其原生状态：适用且有当前证据的项目标为 `completed` 并在内容中附证据；不适用项目也标为 `completed`，内容写 `N/A + 原因`；决策关键证据缺失的项目标为 `cancelled`，内容写 `gap + fail-closed 动作`。交付前读取一次 todo：仍有 `pending/in_progress` 时继续执行；任何 `cancelled` 项未写降级动作时，不得给出干净的“继续持有/买入/卖出”结论。对外可只展示异常、临近触发项和关键缺口；内部闭环不得因用户要求精简而省略。

若使用子代理，账户状态、alerts/L3/Tier和最终交易判断由父级保留。需要提前消费结果的独立证据通道分别派发；只有父级必须同时消费全部结果时才放入同一 wait-all batch。required 证据已齐时，optional 失败不得阻塞首轮交付。

## 日常监控唯一检查表

日常多股或单股复查都按下表顺序输出状态；不适用项写 `N/A + 原因`，不得省略。
动作冲突按 `references/decision-table.json` 的 priority 处理。

| ID | 必检项 | 完成标准 |
|---|---|---|
| C01 | 组合风险 | 明确总资产分母；输出单股权重、当前净值至第二档线潜在回撤、组合潜在回撤；成本口径不一致时输出对账状态 |
| C02 | 持仓框架 | 读取 `holdings --compact --json --active-only` 的 `framework/framework_confident`；未知或`?`则停止框架专属动作 |
| C03 | 活动预警 | 日常先用 `alerts <代码> --active --json`；逐项复核 active/pending 与到期日，需审计生命周期时再读完整视图 |
| C04 | 当日异动 | ≥3%或弱于行业≥2pts时取得同日公告和行业横截面 |
| C05 | 价格止损 | 读取持仓行实际第一/第二档价格，不按列名猜固定百分比 |
| C06 | L3 | `l3-list <代码> --active --json`；只消费当前活动论文的活动条件，逐条输出scope/action、重要性、状态、证据as-of、下次节点、临时出场 |
| C07 | 通用财务恶化 | ROE/扣非两季条件只开红色预警并进入框架复核，不直接清仓 |
| C08 | 估值退出 | 使用对应框架、当次刷新且口径匹配的指标 |
| C09 | Tier/技术 | A/E/F查结构化Tier；技术信号只触发复查 |
| C10 | 动作可执行性 | 区分建议/授权/成交；交易股数通过整手规则；成交后写事件账本 |

C06补充：若输出 `legacy contract`，表示该持仓尚无活动论文版本，部署期间继续按旧L3行为核查但必须显式警告；不得把此兼容路径推广到已重写持仓。若返回“无活动结构化L3条件”或“交易契约无效/已过期”，不得以 notes 补位或输出卖出股数，必须冻结L3交易并重做论文。历史审计使用 `l3-list <代码> --all`。只要任一持仓仍是 legacy、pending、watch 或契约无效，组合摘要必须写“未发现已确认且可执行的交易触发，并保留以下待核实项”，不得写成“全部L3未触发/均已排除”。

## 全局决策契约（跨步骤适用，执行任何单一步骤涉及止损/卖出/加仓/补仓决策时，先对照本节确认是否有适用规则）

### 1. 动作优先级

已确认触发且通过论文版本与语义门的论文破灭型止损（状态机见步骤2）优先级最高，按该条 L3
预设的明确动作执行，不因Tier顺序、加仓规则或分批止盈节奏而推迟。若活动 L3
没有明确动作，禁止把“大幅减仓”等模糊词临场解释为任意股数；升级红色预警并由
用户确认可申报股数。

### 2. "触发"一词的四类含义（仅供辨识用途，不新增规则）

- **①启动核查流程**（本身不是买入/卖出指令）：如价格跌破自设预警位→触发步骤2.5 L3全量核查；价格止损第一档（亏15%）触发→强制重新执行a-stock-research全流程复查（复查本身不构成交易指令）
- **②已满足预设交易条件**：如某条 L3 已确认触发→输出建仓时预设动作及经交易所规则校验后的股数；价格止损第二档→输出目标减仓50%的可申报股数。skill 只生成并记录建议，不代替用户向券商下单
- **③允许性交易动作**（条件满足代表"允许执行"，不代表"必须执行"，是否执行仍需结合当时具体情况判断，完整论述见步骤3.5「使用说明」中与本条的关系）：如步骤3.5分级加仓条件满足→允许加仓，不是必须加仓
- **④进入观察/预警状态**（记录观察，不操作）：如ROE连续2季度下滑>3pts→触发黄色预警

分析结论中引用"触发"时，应同时说明这是哪一类含义，避免读者误判为立即行动指令，尤其不得把①类的"启动核查"误读成②类的"直接交易"，也不得把③类的"允许"误读成②类的"必须"；也不得把步骤2状态机中"候选信号—待确认"状态误当作②类"已确认触发"处理。

### 3. 机械触发规则不得事后追加未预设的例外

任何量化触发规则一旦预设条件全部满足，不得事后用未预设理由改判为“未触发”。本条只在
条件属于当前活动论文、未退役、字段完整且scope/action合法之后适用。但“信号成立”和
“已授权交易”必须分开：只有规则同时定义了动作比例、交易所可申报
股数和用户授权时才写交易账本。动作幅度缺失时，输出“信号已触发、动作未定义”，
打开结构化红色预警并请求用户确认；不得用向下取整推导出0股，也不得把建议伪装成
已成交。预设例外必须可量化并在触发前存在；当前版本不设季末价格止损豁免。

不适用于本身包含主观判断成分的建议性/允许性规则（如步骤3.5的分级加仓——条件本身就包含"至少一项实质性正面证据"这类需要分析者判断的成分，因此不属于本条所指的"纯机械/量化触发规则"范畴）。

### 4. 证据与数据契约

以下要求适用于止损/L3核查、步骤3.5加仓证据、步骤4补仓核查、步骤5年度复查等所有需要举证或引用数据的场景：

- **相关性**：核验止损/L3 条件时引用的证据必须与该具体条件直接相关（如资金流向数据不能作为"H1 净利润是否转正"这类基本面条件的支持依据，即使资金流向看起来是正面信号）。不相关但方向有利的证据不得被用来加强"继续持有"等结论的说服力，应明确区分"公开负面事件层面未发现异常"与"基本面条件本身已核实"两种不同强度的结论。
- **时效性**：评估任何估值卖出信号或L3条件前，须先确认所用数据是当次分析实时获取，不是沿用可能已过期的历史缓存。步骤3详细列出了 fetcher.py 的实际数据覆盖范围及口径缺口，涉及估值指标时须对照该节确认。
- **口径一致，长短窗口须并列披露**：涉及增速/趋势类指标（净利增速、收入增速、ROE趋势等）时，若长窗口（如3年均值）与短窗口（如最近一期/一年）方向相反，须至少同时披露用于本次结论的长窗口口径和最近一期/短窗口口径两个数值，并说明分歧原因是否已查明（如是否为一次性因素），不得仅以较长窗口的正面数值替代最近一期的实际表现来支持"继续持有"等结论。
- **缺失数据不等于已排除/未触发**：若任一 L3 条件尚未定义、无法核验，或状态为「待观察」，不得直接给出"持仓不动/继续持有且无后续动作"的结论。必须同时输出三项：①待补全或待验证的具体 L3 条件；②下一次可验证的数据源和最晚日期（如中报/季报/行业月度数据）；③在验证前的临时出场框架（触发什么数据→减仓/清仓，未触发→继续持有，数据仍缺失→降至半仓或缩短复查周期）。无出场框架的持仓建议视为不可操作。
- **历史预警须先查询**：每次监控核查前，须先查询该股是否已有历史预警记录，不得只看当次即时数据（价格/PE/ROE等）就下"未见恶化"结论——具体查询方法见步骤2「预警机制」。
- **局部专属扩展**（不在此重复全文，只作索引）：判定"行业同步"须用同日横截面数据（步骤2）；排除某条宏观传导路径前须核实对应披露数据（步骤0-3）；E/F框架PEG/PS计算口径（步骤4 Tier2/3）。

### 5. 操作价格依据要求

任何买入、加仓、减仓、止盈、止损、清仓等操作的具体价格目标必须注明来源，可选来源：
- **Tier 触发**：对应 Tier 1/2/3 公式（`reference_cost × 系数`，不得用经济回报成本
  或硬编码值替代）
- **估值信号**：对应步骤3卖出信号表中的具体分位线/溢价条件
- **论文条件**：L3 某一条件触发后的执行动作

禁止给出"无依据价格目标"（如"涨到X元就卖"但未说明X的来源）。若无法立即确定依据，应说明"当前无法确定依据，暂不给出具体目标价"，而非拍一个价格。

### 6. "1/3仓位"全局定义

建仓总量（送转后按同一比例调整）的三分之一，不随已执行操作变化；这是目标比例，
不是委托股数。实际股数必须由 `sell-holding` 校验整手/零股规则：例如沪市整手持仓
500股不能拆成167/167/166股，可采用200/100/剩余200股等最接近目标且可申报的路径。

### 7. 时间基准：buy_date 与主力入场日期

`buy_date` 必须保持为最初建仓日期，不能被后续加仓覆盖（用于步骤5的12个月复查计时）；大额加仓时另有"主力入场日期"字段与之并存，写入规则见「数据操作附录」，消费（读取判断）规则见步骤5。

L2：为什么现在是买入时机，而非1年前/1年后？（时机逻辑）

`tier-config` 选定出场路径；E/F正式仓位若启用Tier1估值豁免，也必须在建仓当日
通过同一命令声明。自由文本 notes 不再作为资格判定来源。

## 步骤2/2.5：日常监控、止损与 L3 硬合同

完整核查步骤按任务路由加载日常监控 reference；以下阈值和 fail-closed 门始终留在主入口：

- 单日跌幅≥3%或弱于行业≥2pts：当日核验公告与同日行业横截面；缺横截面不得判“行业同步”，并设次日开盘前复核节点。行业同步也不能推翻已触发机械规则。
- C框架任何价格止损前分别核验 Q1=`底部区|非底部区|数据不足`、Q2=`已转负|未转负|数据不足`、Q3=`已证伪|未证伪|数据不足`。只有“底部+未转负+未证伪”可在第二档把动作上限保护为减仓50%；任一缺失默认保护不成立，正常执行价格纪律。
- 论文破灭只有两类可确认：活动结构化L3数值阈值达到，或核心业务/监管可持续性/管理层诚信被确定性证据否定。主观/事件条件必须走“候选→待确认→确认”且至少间隔1个交易日；ROE同比连续两季下降>5pts或扣非连续两季同比负增长只开红色预警并做框架复核，不直接交易。`triggered + reduce/exit` 前必须验证活动论文、未退役、scope/action、materiality、证据期和临时出场；失败即冻结交易。
- ROE同比连续两季下降>3pts只开黄色预警。C/D最近单季扣非转负、核心量价连续两个报告期跌破原L3线、或分红FCF覆盖率连续两个报告期<1，仅作为原论文强证伪证据并按状态机处理。
- 价格止损读取持仓行实际第一/第二档价，不按列名或成本猜阈值。当前核对系数：A/E=-15%/-20%，B/D=-12%/-18%，C=-18%/-25%，F=-20%/-28%；持仓行实值优先。第一档只强制重跑 research，第二档目标减仓50%并先算可申报股数；用户确认成交后才能写账本。季末无豁免。自设预警价只启动L3核查，不是止损命令。
- 每次先查 `alerts <代码>`；只有 `holding_deterioration` 黄色预警计入“2项→红色”，`entry_valuation`/`unverified` 不累积。逐项核验 active/pending/resolved、`review_due`；证据不足保持 pending。
- 步骤2.5必须用 `l3-list` 逐条列出全部活动L3的 `触发|未触发|待观察`、证据as-of、下次节点和临时出场。即时指标必须先尝试核验；不可追溯旧L3视为未核查。等待财报时至少为两个关键L3给出达到/低于/中间区间判断树；无法设阈值默认不得加仓。

## 步骤3：估值退出与技术复查硬合同

评估前必须当次刷新并核对值、as-of/window metadata 与 `null_reasons`；字段存在不代表当次必然可得。runtime 可输出 `pe_percentile_5y`、`pe_percentile_10y`、`pb_percentile_10y`、`ps_ttm`、`ps_percentile_5y`；A只用有效PE5年分位，C前瞻股息率另取最新分红方案，E的PEG另取，F可用同口径PS；AKShare手动降级路径不提供同口径PS_TTM。缺失/过期/口径不符必须写“暂不能判定”，不得当作未触发。

估值退出阈值：A PE>近5年85%分位；B PB>近10年70%；C 前瞻股息率<3%；D 股息率-国债溢价<100bps；E PEG>2；F PS>近5年80%且收入增速<15%（两项同时）。科技额外任一“收入增速连续两季<15% / 毛利率下滑>5pts / 核心研发人员离职 / 被监管点名”只触发复查。`3pts=黄色预警入口`、`5pts=红色框架复核入口`，都不直接授权交易。

技术候选满足以下至少2项也只触发复查：连续3收盘日低于60日线且随后5日最高收盘未站回；零轴下死叉且量≥20日均量1.5倍；较60日最高收盘回落>20%。成交后必须用 `sell-holding` 记录实际价、股数、费用和税费，不得只写回报。

## 步骤3.5：C/D框架轻仓试探持仓的分级加仓规则

适用范围：持仓框架为C（资源）或D（公用事业）、且当前定位为"轻仓试探"的持仓，且**L3全部未触发**（L3任一条件触发，不适用本节，直接按步骤2/步骤2.5执行论文破灭型止损）。按"资格→证据→仓位计算→记录"四阶段判断三档动作：维持不动 / 格档小额试探加仓（默认100股，含放大算法和累计上限）/ 正常加仓（升级为正式配置型持仓）。与步骤4"轻仓试探专属出场规则"是按框架分工的并列规则（本节C/D框架专属，判定依据是股息率打分档位；步骤4A/E/F框架专属，判定依据是矩阵仓位建议标签），不是同一机制的重复。

仅在需要为C/D框架轻仓试探持仓做加仓判断时才需要读取完整规则。

**完整规则（含四阶段各自的具体条件、100股放大公式、首次核查基线条款、与全局决策契约第3条的关系说明）见 `references/step3.5-cd-accumulation.md`。**

## 步骤4：分批止盈规则（A/E/F框架，配置型B/D框架用步骤3估值信号出场）

Tier触发必须严格按1→2→3顺序（论文破灭型止损不受此顺序约束，见全局决策契约第1条及步骤2状态机）。Tier1触发线为当前价≥成本×1.25，卖出1/3建仓量（"1/3仓位"全局定义见全局决策契约第6条），E/F框架正式仓位可在建仓当日预声明启用估值豁免（PEG/PS条件不满足时仍需卖出）；轻仓试探持仓另有独立的路径A/B/C出场规则。Tier2/3按框架分别定义PE/PEG/PS触发线，PEG增长率口径已固定为可复算公式（含无机构一致预期数据时的预定义fallback），同一持仓统一口径使用、不得临时切换或择优混用。Tier1卖出后须同时满足价格回落≥12%、**L1/L2/L3核心逻辑完整未变**、估值回落、技术面确认、总仓位<85%全部条件才可补仓，且基本面有任何黄色预警或下跌原因未查明时禁止补仓，历史分位极低时还须先排除行业ROE/盈利中枢结构性下移这一替代解释，不是价格+估值+技术+仓位四项就够。补回成交后必须显式将 `tier1` 复位为 `pending`，Tier2/Tier3 状态不变。缓存 `pe_ttm` 若实际按最新年报 EPS 计算则属于静态 PE，不能冒充真正的 PE_TTM，无法取得真正 TTM 时 PEG 不可计算。除权/送股——**在确认除权日或收到分红入账后**——需按公式重算成本。

仅在处理A/E/F框架持仓的止盈判断、Tier1豁免声明、Tier1补仓或除权成本调整时才需要读取完整规则。

**完整规则（含通用定义、Tier1豁免决策表与声明规则、轻仓出场路径表、Tier2/3各框架具体模板、PEG统一计算公式、Tier1后补仓全部条件、除权成本调整公式）见 `references/step4-tier-system.md`。**

Tier、止损与估值阈值均视为启发式参数；回放数据格式、无前视执行口径和样本外要求见
`references/backtest.md`。

## 步骤5：12个月复查硬合同

执行前必须完成步骤2.5全量L3并读取结构化状态；存在 `watch/pending` 不得判“论文完整”。同时读取最初 `buy_date` 与 `main_entry_date`；主力入场未满12个月时原始与新增仓位分开评估。结论/动作保持：A论文完整且延迟→持有并3—6个月复查；B首次确认对应步骤3估值线→减持1/3建仓量并3个月复查（若持续满足，步骤3更高优先）；C合法活动L3触发→执行其 `action_level`，不得统一清仓；D不可验证→减至半仓并3个月复评。任何动作仍须服从全局授权与可执行股数门。
