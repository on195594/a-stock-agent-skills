# A股投研助手

基本面60分 + 择时20分 = 总分80分（基本面75%，择时25%）。数据源：WebSearch抓取东方财富、雪球、巨潮资讯。
缓存工具：`a-stock-cache`

## 写入安全边界

`holdings`、分析、预警、L3/Tier 和交易账本写入属于 W1：只有在用户确认具体动作后，才可在子命令前追加全局 `--confirm-write`。缺少该参数时 CLI 返回 3 且不打开写事务。数据过期、字段缺失或运行时失败必须 fail-closed，只能报告缺口，不能补造投资结论。

> **方法论说明**：本框架区分"配置价值"（公司值不值得持有）和"时机评级"（现在是不是好买点）。两者独立评分，最终仓位建议由两者共同决定。好公司≠好价格，高股息≠高赔率，这是框架的核心前提。
>
> 用户要求结合 AI、新品发布、旺季或半年产品周期判断行情时，读取 [催化与产品周期参考](references/catalyst-cycle-analysis.md)；必须区分事件催化、订单进度与财务兑现，不能把客户或平台发布直接视为公司订单。

## 数据源边界（TuShare 2000 积分）

- 结构化数据默认使用 TuShare：`daily_basic`、`fina_indicator`、`income`、`balancesheet`、`cashflow`、`dividend`、`trade_cal`。`daily_basic.ps_ttm` 同时提供当前 `ps_ttm` 与同口径 `ps_percentile_5y`；财务端保留完整年报评分基线，并额外输出非评分 `latest_report_snapshot`。
- TuShare 分红接口返回每股口径；`fetcher.py` 在适配层转换为内部每十股口径，缓存字段 `dps` 仍统一表示每股分红（元/股）。
- 实时价格使用新浪单源，并按交易日、交易时段、未来时间和盘中120秒最大年龄校验行情时间戳；这不是 TuShare 2000 积分覆盖的实时行情接口。
- 10年期国债收益率继续使用 AKShare；TuShare `yc_cb` 需要单独权限，不因 2000 积分自动开通。
- 新闻、政策、银行 NIM/不良率/拨备等定性或非结构化信息继续使用 WebSearch。
- 结构化接口故障时可手动设置 `FETCHER_DATA_SOURCE=akshare` 切换旧链路；默认值为 `tushare`。除交易日历外，不自动在 TuShare 与 AKShare 之间切换。

## 有界首版与检索预算

用户只要求“研究/分析/对比”而未明确要求详细审计时，默认交付**有界首版**：保留本 Skill 的全部适用安全门、评分门和标准报告模块，但每个模块只写决策相关证据与结论，不扩展成新闻综述、链接巡检或技术指标大全。用户明确要求详细审计时再扩展证据深度。

- 安装态 `a-stock-fetch` / `a-stock-cache` 是结构化数据与当前价的首选入口。fetch 已成功取得并校验新浪当前价后，**不得再探测其他实时行情 Provider**，也不得用 TuShare/AKShare/第三方网页重复验证当前价；历史涨跌窗口只走已知可用的现有行情入口。
- WebSearch 只补结构化缓存没有的必需事实。优先交易所、监管机构和公司正式披露；通用搜索每批最多 4 个独立查询，每只股票默认最多一批缺口搜索。结果过大或被截断时，缩小到缺失字段，不得重复整批搜索。PDF 同一文件最多使用两种提取路径。
- 完成持仓路由、fetch/check、适用框架、checklist、确定性评分、最新报告冲突门、估值口径门、异动/治理/外部集中风险和形成动作所需的市场情绪后，即达到首版停止条件：**停止新增非阻塞补充检索**，直接生成简洁完整报告并进入 QA。URL 可达性复查、额外研报、重复行情源和不影响结论的技术信号不得阻塞首版。
- 后台 QA 或其他异步任务只依赖宿主完成通知；不得轮询任务状态，不得用 `sleep` 等待。QA 运行期间也不得以“等待时顺便补证”为由修改其输入。

## 持仓路由（最先执行）

股票代码确定时，先只读执行 `a-stock-cache holdings <股票代码>` 核对该股票是否已持仓。可读账本返回 `NOT_HELD <代码>` 才表示已确认未持仓；`HOLDINGS_UNAVAILABLE` 表示账本不可用，不得伪装成未持仓。不得读取单股 monitor 的 `config.json` 代替真实持仓账本。

**确认已持仓后立即终止本 Skill**并改用 `a-stock-monitor`：不得继续执行首次研究的 fetch/check、评分或 QA，不得继续加载首次研究框架引用。只有用户明确要求重新做首次配置研究，才可在说明与当前持仓监控结论分离后继续本 Skill。账本不可用时须标注路由证据缺口；可以继续公开市场研究，但不得声称该标的是新仓，也不得据此给账户级仓位动作。

## 缓存检查（路由确认后，在第零步之前）

**必须按下列顺序串行执行，禁止并行**。只有 `fetch` 成功后才能运行 `check`；`fetch` 失败时停止并报告数据缺口，不得读取可能陈旧的状态继续评分。⚠️ **禁止用 WebSearch 获取当前股价**——fetcher 使用新浪单源，并按交易日、交易时段、未来时间和盘中120秒最大年龄校验行情时间戳；新浪不可用或行情过期时行情获取失败。

```bash
# 必须先成功完成
a-stock-fetch fetch <股票代码>
# 仅在上一条命令成功后执行
a-stock-cache check <股票代码>
```

输出状态码处理：
- `ANALYSIS_HIT`：今日分析结论已缓存，直接输出结论，附注"[来自今日缓存]"，**终止流程**
- `FUNDAMENTALS_HIT`：基本面有缓存，直接使用缓存数据：
    - **以下字段从缓存读取，跳过搜索**：静态PE（`pe_static`；旧字段 `pe_ttm` 仅为 deprecated 兼容别名，不能作为真正 PE_TTM 用于 PEG）、PB、ROE、净利润增速、负债率、股息率、每股分红（dps）、PE历史5年分位（`pe_percentile_5y`）、PE历史10年分位、PB历史10年分位、PS_TTM（`ps_ttm`）、PS历史5年分位（`ps_percentile_5y`）、最新中报/季报方向快照（`latest_report_snapshot`）、10年期国债收益率、流通比、毛利率、收入增速、流动比率、每股经营现金流、基本每股收益、每股净资产（bps）
    - **⚠️ B银行框架必须补搜（AKShare 无此字段，不可跳过）**：净息差（nim）、不良贷款率（npl_ratio）、拨备覆盖率（provision_coverage）。保险/券商不进入 B 框架，只做定性摘要后终止量化评分。
    - **⚠️ B框架银行 WebSearch 补搜失败降级规则**（仅适用净息差/不良率/拨备三字段）：
      - 单字段缺失：该维度记0分（净息差→0/10；不良率→0/15；拨备覆盖率→0/10），并在输出格式第5项前标注"⚠️ B框架[字段名]数据缺失，对应维度0分，基本面总分可靠性受限"
      - 三字段全缺：报告首部置顶"⚠️ B框架核心数据不可获取，本次评估结果不适用于投资决策，须补充数据后重新执行（建议直接查阅[公司名]最近年报或银行业监管信息披露页）"；**B框架三项核心数据全缺时必须 `scoring_status=incomplete`，停止基本面总分、时机评级、综合总分和仓位矩阵，不得把三个0分包装成完整结果**
    - **只补缓存缺口**：异动、治理/政策与外部集中风险；B银行框架另补净息差/不良率/拨备覆盖率。实时价格已由 fetcher 获取，不得用 WebSearch 重新获取价格
- `FULL_MISS`：完全未命中，执行下方完整分析流程

**⚠️ 股息率交叉验证（仅 FULL_MISS 必做；FUNDAMENTALS_HIT 直接信任缓存 dps，跳过本节）**：
1. 搜索获取：`[股票] 每股分红 最近完整年度`
2. 计算值 = 每股分红（dps） ÷ 当前实时股价
3. 若缓存/搜索值与计算值误差 > 0.5%（50bps），**以计算值为准**并在报告中标注差异原因（通常是股价变动导致）
4. 评分和操作建议均使用验证后的股息率，不得直接引用未经验证的缓存值；**FUNDAMENTALS_HIT 豁免：缓存 dps 视为已验证，可直接用 dps ÷ 实时股价计算股息率后引用**
5. B银行框架补搜三项核心字段，FUNDAMENTALS_HIT 和 FULL_MISS 均必做；**dps 验证搜索仅 FULL_MISS**：FULL_MISS 时银行额外搜 `[银行名] 每股分红 派息`；FUNDAMENTALS_HIT 时直接用缓存 dps，不再搜 dps

**⚠️ 数据口径标注（所有框架必做）**：
- ROE、NIM、净利增速等财务指标必须标注来源报告期，格式：`ROE 13.44%（2025年报）`
- 若缓存中 `data_period` 字段早于上一个完整年报，前置警告：「⚠️ 数据可能已过期，建议补搜最新年报」
- PB 必须使用当前已验证股价 ÷ 与历史 PB 分位相同报告期/复权口径的 BPS 计算，并同时列出股价时点、BPS 报告期和公式。若报告列示 PB 与重算值相差超过2%，视为口径冲突：PB、PB分位和择时估值均标记不可用，停止输出时机总分、综合总分和仓位矩阵，不得用第三方不同报告期 PB 继续评分。

**⚠️ 最新中报/季报冲突门（所有量化框架必做）**：当前结构化财务缓存以完整年报口径为主。先读取非评分 `latest_report_snapshot` 核验年报后是否已披露更新的中报/季报；如有，至少核对收入、扣非净利润、ROE/净资产及对应框架核心变量的方向。快照字段缺失时再查公司正式披露，不得把缺失方向补成“无冲突”。若新一期与缓存年度趋势方向冲突，或无法取得同口径数据完成核验，则 `scoring_status=incomplete`，停止配置评级、时机评级、综合总分和仓位矩阵；不得用单季利润机械年化替代TTM，也不得把“年报仍在TTL内”视为最新财务状态。

**⚠️ 行业路由新鲜度门**：fetcher 输出 `industry_status=stale_cache` 或 `missing` 时，历史行业只可展示，不得用于选择 A—F 框架、推断止损系数或形成量化结论。必须从公司最新正式披露核验主营业务后再路由；核验失败则终止量化评分并标记 `scoring_status=incomplete`。

## 分析完成后写入缓存

```bash
# ① 写入今日分析结论 + 框架 + 综合得分（框架必填；得分可选）
# 框架就是第一步行业识别时已经决定的那个（A通用/B银行/C资源/D公用/E消费/F科技），
# 直接传进来持久化，避免后续 add-holding/portfolio-risk 再靠 industry 关键词反推失真
a-stock-cache --confirm-write set-analysis <代码> <框架> <得分> << 'ANALYSIS_EOF'
<完整分析报告全文>
ANALYSIS_EOF

# 框架可用 A—F 简称或完整标签。未知参数、冲突框架、重复/越界得分均拒绝写入。
# D公用缺少24小时内可信国债收益率时：不传得分；报告只保存基本面小计，
# score=null、timing.subtotal=null、scoring_status=incomplete，禁止伪装成完整80分结果。

# ② 事后补录得分（向后兼容，需先执行 set-analysis）
a-stock-cache --confirm-write set-score <代码> <得分数字>

# ③ 写入基本面数据（TTL 按行业自动推断：银行/公用72h，消费12h，其余24h）
a-stock-cache --confirm-write set "<代码>" "<名称>" "<行业>" '<JSON>'

# ④ 若触发红线/黄线，记录预警（可多次调用追加）
# ⚠️ 注意：set-flag 依赖今日已存在 set-analysis 记录，必须先执行 ① 再执行 ④
a-stock-cache --confirm-write set-flag "<代码>" red "<红线原因>"
a-stock-cache --confirm-write set-flag "<代码>" yellow "<黄线原因>"
```

JSON数据结构示例：
```json
{"roe_3y_avg": 12.1, "gross_margin": null, "data_period": "2025年报",
 "null_reasons": {"gross_margin": "银行不适用"},
 "field_provenance": {
   "roe_3y_avg": {"source": "tushare", "as_of": "2025年报", "status": "ok"},
   "gross_margin": {"source": "tushare", "as_of": "2025年报", "status": "missing"}
 }}
```
> **字段说明**：`data_period` 为数据来源报告期（必填，如 "2025年报"/"2026Q1"）；`dps` 为每股分红（用于股息率交叉验证）；`pe_static` 是当前价÷最近完整年报EPS；`pe_ttm` 暂时保留为同值的 deprecated 兼容别名，绝不代表真实TTM。`pe_percentile_5y` 使用相同静态PE口径、披露滞后处理和近5年价格窗口。

## 预筛选：格雷厄姆估值门槛（强制，在第零步之前执行）

搜索获取：`[股票名称] EPS每股收益 每股净资产`
计算：格雷厄姆数 = √(22.5 × EPS_TTM × 每股净资产)
买入参考价 = 格雷厄姆数 × 0.85

判断逻辑（按框架分类，以下替换原一刀切规则）：
- **EPS_TTM ≤ 0（亏损企业）**：跳过格雷厄姆数，标注"EPS为负，无格雷厄姆参考，改用框架主估值轴"，继续分析
- **B框架（仅银行）**：跳过格雷厄姆数，改用 PB < 1.0 作为安全边际判断标准
- **F框架（科技/互联网）**：跳过格雷厄姆数，改用 PS历史分位 + PEG 作为主估值轴（格雷厄姆数对负自由现金流科技公司无意义）
- **A框架（通用制造/医药/建筑等）**（A股制造类PE通常15-40x，格雷厄姆数隐含PE上限约15x）：
  - 股价 ≤ 格雷厄姆数：标注"有安全边际（格雷厄姆标准）"
  - 格雷厄姆数 < 股价 ≤ 格雷厄姆数 × 2.0：标注"A框架合理溢价区间，不置顶"
  - 股价 > 格雷厄姆数 × 2.0：置顶"⚠️ 格雷厄姆警戒：股价超出格雷厄姆数2倍"
- **E框架（消费/白酒/零售等）**（消费品牌PE/PB普遍高于格雷厄姆数隐含值）：
  - 股价 ≤ 格雷厄姆数 × 1.5：标注"有安全边际（格雷厄姆标准）"
  - 格雷厄姆数 × 1.5 < 股价 ≤ 格雷厄姆数 × 3.0：标注"消费品溢价区间，不置顶"
  - 股价 > 格雷厄姆数 × 3.0：置顶"⚠️ 格雷厄姆警戒：消费品溢价超出3倍，评估品牌溢价可持续性"
- **C框架（能源/资源）/ D框架（公用事业）**：股价 > 格雷厄姆数时标注"格雷厄姆无安全边际（参考）"（不置顶，C/D主估值轴为股息率/FCF）；股价 ≤ 格雷厄姆数时标注"有格雷厄姆安全边际"
  - ⚠️ C框架若判定为**成长型资源股分支**（派息率<40%，见 `frameworks/C.md`），主估值轴改为 PB历史分位，本条「C/D主估值轴为股息率/FCF」的表述不适用于该分支；格雷厄姆数的处理方式不变，仍为参考项。

## 第零步：异动检测 + 防韭菜预检（合并为单次搜索）

搜索：`[股票] [代码] 涨停 连板 异动 大股东减持 大宗交易 风险提示 最新`
> 搜索完成后立即提取两个信息点，各 1-2 句：
> ① **异动信号**：5日涨跌幅、是否涨停/连板、有无风险公告
> ② **减持/大宗信号**：有无大股东减持公告、大宗交易折价（有则标注，无则"无异常"）
> 不展开新闻正文。

若5日内涨停/连板，或3日涨幅>15%，标记为「异动股」：不终止分析，继续完整流程，但强制执行以下两条约束（在第三步择时评分中落地）：
①「市场情绪」分直接计 0 分，并按下方唯一计算顺序追加 -3 分；
② 时机评级最高只能给 ★（≤12/20）；该上限在双轨矩阵输出前统一应用，不再对矩阵结果二次乘比例。
结论首部置顶「⚠️ 近期异动，存在追高风险，建议等待回踩确认」。

政策风险搜索：`[股票] [行业] 监管 政策 <当前年度> 最新`
> 搜索完成后立即提取：政策方向（支持/中性/压制）、主要事件（1条）。结论1句。

若搜索结果显示：行业处于政策压制期（限价/退出/整顿）→ 在结论首部置顶"⚠️ 政策逆风"警告，不终止分析但强调谨慎

## 第二步：基本面评分（60分）

> **风险降级规则**：风险项触发时直接扣减对应维度得分，规则见各框架文件。

> **⚠️ 主观分项证据门槛**（适用所有框架的护城河/行业地位/特许经营稀缺性/品牌渠道类条目）：这类指标无客观数据可直接打分，容易凭印象/知名度给虚高分。打"强/优"档前必须列出至少1-2项可验证证据（如：近3年提价但销量未下滑、客户流失率数据、市占率连续提升趋势、特许权剩余年限及续约历史），缺乏证据支撑时该维度最高只能打"中等/格"档，不得仅凭公司知名度或主观印象判断。完成每个适用类别的最终判断后，必须追加该类别的结构化标签，格式为 `<类别>[评级=<优|格>；证据="<证据1>";"<证据2>";置信度=<高|中|低>]`。六框架的展示项必须映射为标准标签：A/B 的护城河→`护城河`；C 的储量竞争力→`护城河`；D 的特许经营稀缺性→`特许经营稀缺性`；E 的品牌/渠道→`品牌渠道`；F 的订单能见度/客户留存→`护城河`；所有框架的行业地位→`行业地位`。每份报告必须同时包含该框架映射后的两个标签。示例：`护城河[评级=优；证据="近3年市占率连续提升";"提价后销量未明显下滑";置信度=中]`。证据文本两侧必须使用 ASCII 双引号 (`"`)，不得使用中文全角引号（“ ”）；这是解析器只识别 ASCII 引号的硬约束，不是格式偏好。同一类别最多只有一个标签会被识别；若报告后文修正同一类别判断，解析器仍只读取首次出现的标签，因此不要在该类别判断最终确定前输出标签。

> **⚠️ A框架外部集中风险覆盖**：A框架每次都必须输出 `外部集中风险[状态=正常|受限|重大；证据="<正式披露1>";"<正式披露2>";置信度=<高|中|低>]`。正式披露未显示单一客户/地区高度集中或相关重大跨境限制时，输出“正常”及核验依据；存在集中敞口、限制、制裁、名单或未决实体裁决时，按证据输出“受限”或“重大”。该标签不改 A 框架60分结构；状态为“重大”时，配置分和配置级可展示，但必须紧邻标注“置信度受限”，且不得因满分或A级自动升级动作。最终动作仍只服从既有双轨矩阵、异动、治理及组合约束，不另建第二出口。

> **⚠️ 客观分项核验门槛**（适用所有框架经 `cache.py checklist` 核验过的子项）：checklist 输出的"达优/达格/未达/数据缺失"是分析代理打分的硬约束，不能违背，但留有裁量空间：
> - **达优**：最高给满分；若该子项 `data_status` 标"简化判定（不判断趋势/连续性）"，除非分析代理自行核实了历史趋势/连续性，否则只能按达格档给分。**若分析代理自行核实后**（无论核实结果推翻还是维持 checklist 的简化判定值），该子项一律标注「人工核验推翻简化判定」，并在标签后注明核实出的实际档位（达优/达格/未达）及依据，不得沿用「checklist核验」标签（该标签仅用于未经额外核实、直接采信 checklist 原始结果的子项）
> - **达格**：最高只能给格档分，**除非该子项 note 写明"优档需人工判断"**（如C框架净利润趋势、F框架经营现金流质量），此时可结合框架文档质性条件+证据上调至优档
> - **格档折算比例（全框架通用）**：框架文档只写"优/格"条件而未写具体分值时，**格档一律按该维度满分的 50% 计**（如 [10] 的维度格档给5分，[15] 给7.5分）。此前 A/E/F 框架曾按 60% 隐性推断，自 v3.2.0 起统一为 50%，与 `frameworks/B.md` 已显式写明的口径（净息差5/10、不良率7.5/15、拨备5/10）一致。框架文档已显式写明分值的，以框架文档为准。
> - **未达**：只能给0分或框架红线扣分，**除非该子项无格档数值线**（如A框架毛利率——"无明显下滑格"是质性判断），此时可结合框架文档质性条件+证据判定能否给格档分
> - **数据缺失**：标"⚠️ 数据缺失，未核验"，按0分计入；任意 checklist 覆盖字段缺失均触发输出格式第1项的前置警告（不止毛利率/PE分位/股息率三项）
> - **checklist未覆盖项**（如C框架压力测试股息率、F框架研发强度）：权重不变，按框架文档原样人工判断，标"⚠️ 无客观数据支撑，纯人工判断"
> 与第1.5步周期折扣的叠加顺序：先用 checklist 结果（含上方裁量空间）定出子项基础分，再叠加第1.5步周期折扣（如顶部区ROE评分×50%），checklist 不参与周期折扣计算。

> **⚠️ 汇兑损益剔除规则**：若财务费用中汇兑损益导致当季/当年净利润出现重大扭曲（汇兑波动金额 > 该期净利润绝对值的30%），评估净利润增速时**必须计算同口径的经营性净利润增速**——即当期与对应基期均剔除汇兑损益后再计算增速，避免单边剔除导致比较基准失真；以同口径经营性增速作为框架净利增速维度打分的主要依据，表面净利润在报告中标注即可。（来源：2026-06-29 比亚迪Q1 2026 agy Critical审查；汇兑摆动约-40亿，表面-55.38%，同口径剔除后仅-14.7%）

## 第三步：择时评分（20分）

> 评分体系：基本面60分 + 择时20分（估值15分 + 市场情绪5分）= **总分80分**；技术信号为参考项，不计入总分，附在结论末尾。

**估值信号（15分）——以各框架主估值轴为准**

| 框架 | 主估值轴 | 买入信号（满分15） | 次级参考 |
|------|---------|-----------------|---------|
| A通用 | PE历史分位 | PE低于近5年50%分位 | 格雷厄姆数 |
| B银行 | PB历史分位 | PB低于近10年30%分位 | ROE趋势 |
| C资源 | 归一化FCF股息率 | 前瞻股息率>5%（压力测试后）+ 周期底部区/上行期 | 格雷厄姆数（参考） |
| C资源 | PB历史分位（**仅成长型资源股分支**，派息率<40%，判定见 frameworks/C.md） | PB低于近10年40%分位 + 周期底部区/上行期 | 产量复合增速、格雷厄姆数（参考） |
| D公用 | 股息率vs国债溢价 | 溢价>200bps | 股息增长趋势 |
| E消费 | PEG | PEG<1；或PE低于近5年40%分位 | 格雷厄姆数 |
| F科技 | PS历史分位 | PS低于近5年40%分位；有盈利时PEG<1.5 | — |

> **估值能力与确定性计分门槛**：A/E/F 使用近5年分位时，**不得用10年分位替代5年分位**；E/F 使用 PEG 时必须取得真实 TTM 盈利与可复核增长口径，缓存静态 `pe_static`（及 deprecated 兼容别名 `pe_ttm`）不得代替；F 使用 PS 时必须取得同口径近5年 PS 历史分位。满足本表已定义买入信号且证据完整时估值记15分；证据完整但未满足时**估值项记0/15**。所需5年分位、PS、真实PEG、报告期或交叉估值任一缺失/冲突时，估值项进入 `incomplete`，不得自创中间分，也不得输出时机评级、综合总分或仓位矩阵。

> ⚠️ **C资源占两行**：上一行为成熟资源股分支（默认，派息率≥40%，轴为归一化FCF股息率），下一行为成长型资源股分支（派息率<40%，轴为PB历史分位）。分支判定见 `frameworks/C.md`。**框架代号统一仍为 `C资源`**，`cache.py set-analysis` 等命令不接受 `C资源(成长型)` 这类带后缀写法。
> 成长型分支择时采用 PB历史分位而非股息率或 PE 的理由：低派息是再投资配置选择、不是估值信号；周期顶部利润处峰值会造成 PE 低估假象（紫金601899 于 2026-08-06 实测 PE 10年分位21.0% 而 PB 10年分位76.8%，即此形态）；PB 更接近储量资产的重置价值；PB 分位必须结合周期位置判断，避免下行期低 PB 的价值陷阱。40%分位沿用 E消费/F科技 口径，不采用 B银行的30%口径（银行常年破净，PB 分布形态不同）。
>
> **成长型资源股估值冲突门**：PB 分位只是主轴，不是单证据硬判。必须再核验至少一个前瞻或周期归一化指标（中周期盈利估值、简化 NAV、或 EV/EBITDA；披露商品价格、产量、成本和报告期假设）。不得用单期利润机械年化替代。若 PB 结论与交叉估值方向冲突，输出 `估值冲突[状态=待核实；PB结论="<结论>"；交叉估值结论="<结论>"]`；该项不得记 0/15，也不得输出时机总分、综合总分或仓位矩阵。`set-analysis` 不传得分，待正式报告或可复核假设消除冲突后重评。

> ⚠️ **D框架择时上限**：若溢价<150bps，本步骤（择时评分）上限为10/20，无论其他信号多强。

> 注：当主估值轴与格雷厄姆数结论冲突时，**主估值轴优先**，需在报告中明确说明冲突及裁决依据。

> ⚠️ **送转股/股本扩张不影响历史分位可比性**：10送X、10转X、资本公积转增等股本扩张后，行情软件历史PE分位均采用**后复权EPS+除权调整价格**自动重算，历史比较基准不失效。不应以"送转股导致历史基准不确定"为由对PE历史分位估值得分额外折扣。（来源：2026-06-29 比亚迪10送20 agy Critical审查）

> ⚠️ **历史分位极低时须做反向解读检验**：分位<5%时，存在两种解释：①历史均值回归（便宜）；②行业ROE/盈利中枢结构性下移（历史均值失去参考价值，不是便宜）。两种解释均与数据兼容时，**必须在报告中明确排除后者**（例如：引用最新季报ROE趋势、NIM企稳信号、行业政策环境），不得仅凭分位数低直接断言"历史低估"。（来源：2026-07-02 招商银行 agy Important审查）

**市场情绪（5分）**：只有融资余额状态和近期涨停/连板热度均有可核验时点、且均无极度亢奋信号时记5分；任一明确亢奋时记0分；任一数据缺失时择时项 `incomplete`，不得凭“未搜到异常”给5分。
> ⚠️ 第零步标记为「异动股」时：本项计 0 分，按唯一计算顺序追加 -3 分，时机评级上限强制为 ★（≤12/20）；不得在矩阵输出后再次减半，避免重复处罚和第二动作出口。

**预期差、除权/除息、市场风格与异动调整（必做/按条件触发）**：详细证据门、分级扣分和可证伪要求见[择时调整细则](references/timing-adjustments.md)。任一必需输入缺失时继续执行本节既有 `incomplete` 门，不得凭“未搜到异常”补分。

> **择时总分唯一计算顺序**：`raw = 估值分 + 市场情绪分 + 周期调整 + 预期差调整 + 除权/除息调整 + 市场风格调整 + 异动股调整`。周期调整仅顶部区为-3，其余阶段为0；异动股调整为-3；其他调整只取本节明确档位。先算 `bounded=max(0,min(20,raw))`，再应用 D框架溢价<150bps 的10分上限及异动股12分上限，得到最终择时分。任一必需输入 `incomplete` 时不计算 raw/总分，不得遗漏项目、重复扣分或改变顺序。

注：搜索获取的MACD/均线时效性无法保证时标注"待核实"，仅作参考。

## 第四步：双轨评级与仓位建议

> 基本面分数反映"公司质地"，择时分数反映"买点质量"。两者独立，仓位由两者共同决定。

> **D框架数据完整性门槛**：缺少24小时内、来源完整的10年期国债收益率时，只输出基本面小计；`timing.subtotal=null`、综合 `score=null`、`scoring_status=incomplete`，不得输出时机星级、仓位矩阵结论或伪装成择时0分。

## 质量合规检查（每次产生新分析后自动触发）

**触发豁免**：ANALYSIS_HIT 路径直接输出缓存结论，跳过 QA（无新分析内容可评估）。

完整分析报告输出完成后，先将正文冻结为**不可变快照**：优先直接按值传入；若使用文件，必须写入本轮唯一版本路径并记录内容哈希，QA 返回前不得覆写。任何正文修订都必须生成新快照并重新执行 QA，旧 verdict 只适用于旧快照。随后通过当前宿主的 Skill discovery/invocation 调用
`a-stock-qa`，传入 `skill_type=a-stock-research` 和该完整报告快照。宿主无法发现或执行
该 Skill 时，明确标记“QA 未执行”及原因；不得把未执行伪装为通过，也不得改用
客户端专属命令或子代理名称。

异步宿主必须依赖完成通知，不得轮询 QA 状态，不得用 `sleep` 等待，也不得在 QA 运行期间继续修改或补充其输入快照。

QA 返回后，冻结正文仍不得覆写。下方规定的 verdict 标记属于交付元数据：需要文件交付时，从冻结正文生成新的交付副本并只追加对应的固定标记；任何其他正文变化都必须成为新快照并重新 QA。

**根据 verdict 处理**：
- COMPLIANT → 在报告末尾追加一行：`✓ a-stock-qa 合规检查通过`
- PARTIAL → 在报告末尾追加：`⚠️ a-stock-qa Minor问题：[FAIL检查项及说明（来自QA明细表）]`
- NON_COMPLIANT → **在报告首部置顶警告**（重新输出报告开头）：`⛔ a-stock-qa：以下步骤存在合规问题，报告可信度降低：[FAIL检查项及说明]`
- INVALID_RUN → 在报告末尾追加：`⚠️ a-stock-qa 输入无效，未形成合规结论：[原因]`；不得表述为报告不合规或合规通过
- SKIP → 在报告末尾追加一行：`⚠️ a-stock-qa 未执行：[原因]`

QA 发现 Critical/Important 问题时，只修正本次报告并说明根因。若根因疑似框架规则，
仅提出变更建议；不得在普通投研请求中修改 `SKILL.md`、framework、rubric、版本或
changelog。投资规则变更仍须独立 dated spec 和用户直接授权。
